# TRAE Demo Wall项目概要设计 v0.7

## 1. 版本目标

v0.7 在 v0.6 的基础上进行种子数据优化和文档体系重构，提升项目的企业级规范性和可维护性。

## 2. v0.7 核心变更

### 2.1 种子数据优化
- **硬编码核心业务字典**: 将审核状态、开发状态、作品分类、荣誉类型等核心数据直接写在 seed.ts 中
- **省份城市数据分离**: 创建独立的 `seed-data-countries.ts` 文件存放 424 条省份城市数据
- **删除数据库导出依赖**: 不再从 `docs/seed-data.ts` 导入大数据文件（67KB → 0）
- **增强日志输出**: 区分"新建 X 条"和"跳过 Y 条"，便于首次部署和更新部署的识别

### 2.2 环境配置标准化
- **双模板策略**: 本地开发 `.env.example` + Docker 部署 `.env.docker.example`
- **占位符替代真实密钥**: 所有配置文件使用 `your-xxx-here` 格式
- **详细的中文注释**: 每个配置项都有说明和使用示例

### 2.3 文档体系重构
- **新建 database/ 目录**: 统一管理 Schema、迁移文件和种子数据
- **整合 design/ 目录**: 概要设计 + TRAE 需求文档集中管理
- **优化 archive/ 目录**: 重命名为更简洁规范的名称
- **完善 README.md**: 详细索引所有文档，新增维护规范

## 3. 架构改进

### 3.1 Seed.ts 新架构

**之前方案**:
```
seed.ts → import → docs/seed-data.ts (67KB, 3592行)
```

**现在方案**:
```
seed.ts (350行自包含)
  ├── 硬编码核心字典（角色、审核/开发状态、作品分类、荣誉类型）
  └── import → docs/seed-data/countries.ts (424条省份城市)
```

**优势**:
- ✅ 核心逻辑与大数据分离
- ✅ 便于代码审查和维护
- ✅ 减少 67 KB 的文件体积
- ✅ 支持完整的 Git diff

### 3.2 数据库 Schema 管理

**推荐流程**:
1. 修改 `prisma/schema.prisma`
2. 运行 `npx prisma migrate dev <name>` 创建迁移
3. 迁移文件自动保存到 `database/migrations/`
4. 历史迁移自动归档到 `database/migrations/archive/`

**Schema 文件结构**:
```
database/
├── schema.sql                    # Schema 概述文档
├── schema-latest.sql             # 最新导出
├── schema-archive-v0.sql         # 旧版归档
├── migrations/                   # Prisma 迁移
│   ├── 20260807120632_init/      # 初始迁移
│   └── archive/                  # 历史迁移 v0.1~v0.7
└── seed-data/                    # 种子数据
    ├── countries.ts              # 省份城市（TypeScript）
    ├── backup/                   # JSON 备份
    └── seed-from-db.ts.backup    # 原始导出备份
```

## 4. 环境变量最佳实践

### 4.1 本地开发（.env.example）

```bash
DATABASE_URL="postgresql://postgres:postgres@localhost:5433/trae_demo_wall_dev"
DIRECT_URL="postgresql://postgres:postgres@localhost:5433/trae_demo_wall_dev"
REDIS_URL="redis://localhost:6379"
NEXTAUTH_SECRET="your-secret-key-here"  # 生成方式: openssl rand -base64 32
COS_SECRET_ID="your-cos-secret-id-here"
COS_SECRET_KEY="your-cos-secret-key-here"
```

### 4.2 Docker 部署（.env.docker.example）

```bash
DATABASE_URL="postgresql://postgres:postgres@db:5432/trae_demo_wall?schema=public&connection_limit=20&pool_timeout=20"
REDIS_URL="redis://redis:6379"
RUN_DB_INIT=true        # 首次部署设为 true
START_SERVER=true        # 应用容器启动服务
NEXTAUTH_SECRET="CHANGE_ME_USE_OPENSSL"
```

## 5. 文档组织

### 5.1 目录结构

```
docs/
├── README.md                     # 总索引（已更新）
├── guides/                       # 开发指南（6个文件）
├── design/                       # 设计文档（9个文件）
│   ├── v0.1 ~ v0.7              # 概要设计
│   ├── 页面设计文档
│   ├── 产品需求文档
│   └── 技术架构文档

├── superpowers/                  # 功能规格（4个文件）

```

### 5.2 文档命名规范

**概要设计**: `{日期}_DemoWall项目概要设计_v{版本号}.md`
- 例: `20260808_DemoWall项目概要设计_v0.7.md`

**功能文档**: `{功能名}-document.md`
- 例: `page-design-document.md`、`product-requirements-document.md`

**指南文档**: `{类别}-reference.md` 或 `{类别}-guide.md`
- 例: `api-reference.md`、`development-guide.md`

## 6. 适用边界

**适用场景**:
- ✅ Next.js + Prisma + Docker 多服务部署项目
- ✅ 需要清晰的种子数据管理
- ✅ 企业级开源项目文档规范
- ✅ 双环境（本地开发 + Docker 部署）配置

**不适用场景**:
- ❌ 纯本地开发项目（无需 Docker）
- ❌ Serverless 架构
- ❌ 不需要环境隔离的小项目
